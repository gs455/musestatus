v1.2.010/28/26

The burger menu's two history entries become one — Code History / CL — opening the code-history page, which now carries a Changelog button in its bar (the /artifacts arrangement); this page keeps its Brief/Full tabs and links back. The Shortcuts popup follows: a single “Code History / CL” task on H, with L free. The burger also gains “How to use”, a Shortcuts-style popup guide you can edit in place, and a new V shortcut opens the burger menu at your cursor.

The saved-shortcuts migration runs once: if your Changelog/Code history keys still sat at the old stock L and H, the L entry is dropped so the combined task stands alone on H; any key you customized is left exactly as it was. The How to use text saves into the synced view state (howToUseText, empty = stock) with Save and Revert to stock, exactly like /artifacts. V is distinct from bare Ctrl: Ctrl toggles the menu at the burger button, V toggles it wherever the mouse last was, and Esc closes it either way. Behind the scenes, the code-history generator's version regex was fixed — its changelog bullets had silently rendered empty since v1.1.0; each release section there now shows its changelog text above its commits, as intended.

v1.1.110/28/26

The Shortcuts popup gets a new stock key: S toggles it open and closed (Esc still closes it too), mirroring /artifacts, and K is freed. If you had never customized that key, nothing changes for you beyond the letter — a saved override still pinning the old stock K is migrated once on load, and any key you chose yourself is left exactly as it was.

The burger menu also gains an "Instant tooltips" toggle, off by default: with it off, the page's custom tooltips (the Shortcuts button's list, the clipped-text cell tip) appear after a short 0.2s hover instead of instantly; turn it on to restore the old instant behavior. The setting syncs with the rest of the view state.

v1.1.010/28/26

Ten new panes bring what the sibling status apps show to musestatus: Plugins (adapted), Claude Code versions, Local setup, Recent activity, GitHub repos, Cloudflare Pages, Disk usage, CLI versions, Workflows & playbooks, and a Collector error log. New panes are tinted green with a NEW chip for this release. The burger menu gains a History section (this changelog plus a generated code-history page) and an assignable Shortcuts system, and every table gains claudestatus-style columns — double-click a header to rename it, double-click its edge to clear its width.

The publisher (~/workspace/muse-status-app/publish.py) learned ten collectors: light ones ride the existing run (latest question per chat, largest home folders from the file walk's new per-directory sizes, and collector failures read from the hook logs and the publisher's own new run log); deep ones run on the 8-hour pass (connector/skill bundles, Claude Code versions probed over SSH per machine with the highest found treated as latest, this VM's MCP servers and instruction files, GitHub repos with their latest commits, all 38 Cloudflare Pages projects paged through the API, CLI version probes, and saved workflows — honestly none on disk — plus the custom-skill playbooks). Panes whose source cannot be read keep their previously published data; the section payloads carry isNew only for this release.

Shortcuts: E edit mode, bare Ctrl burger menu (armed on keydown, fired on keyup, cancelled by any other key), A expand/collapse all, B left task pane, W wrap, T theme, P Panes panel, L changelog, H code history, K shortcuts. The Shortcuts popup captures new keys per task, flags conflicts in red without stealing them, and persists assignments in the synced view state like everything else.

v1.0.010/23/26

musestatus launches: a data-driven status page for the Muse environment — 12 panes (Starred & pinned, File system, Preferences, Machines, Connectors, Usage & billing, Automations, Skills, Tools, Assistants & chats, Artifacts & hub, Memory). Data is collected on this VM by a publisher cron and served from D1 behind the hub proxy; every pane is reorderable, hideable and collapsible, every table's columns sortable, renamable, resizable and draggable, and the whole view state syncs across devices.

Same-night storage migration: sections first published into a KV namespace, then moved to D1 (musestatus_sections / musestatus_chunks / musestatus_view_state in the shared anvari-hub database) once KV's write budget proved too tight; the publisher is hash-gated at both layers, so a run where nothing changed writes nothing. The worker gates every route except publishing behind the hub proxy key, and the app lives only at its hub path — the backend origin is never linked.
